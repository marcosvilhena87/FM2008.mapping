# Protocolo de verificação independente — ID e nomes (8.0.2v1)

**Estado: coleta externa pendente. Sem aprovação de mapa.** Este protocolo preserva a separação entre dados gerados pelo leitor experimental e evidência que não deriva dele.

## Material existente

- `fm2008-8.0.2v1-observed-player-identities.csv`: dez registros observados, cinco por partida, transcritos dos diagnósticos do `ReadOnlyProbe`. **Não são referências independentes**.
- `fm2008-8.0.2v1-independent-reference-template.csv`: roteiro de confronto, **ainda não conferido**. Os nomes pré-preenchidos foram copiados da tabela observada apenas para orientar a navegação — não são prova.
- `scripts/verify_player_identification.py`: compara os dois arquivos, sem abrir o jogo e sem acesso à memória. O resultado é sempre `approved: false` e `operational: false`.

## Procedimento no FM2008

1. Abrir a partida correspondente. **Não presumir** que o jogo exiba o ID interno; em muitos perfis somente o nome é visível.
2. Procurar, pelo próprio mecanismo de busca do jogo, os jogadores descritos no CSV. Confirmar primeiro nome, sobrenome e, quando visível, nome comum. Registrar na referência o nome efetivamente exibido e a proveniência independente (por exemplo, `source_type=game_ui`, `source_detail=Perfil do jogador em [partida], data/etapa da consulta`, e um identificador de `reviewer`). Se o jogo exibir apenas nome completo, registrar a limitação: a divisão entre primeiro nome/sobrenome não foi necessariamente demonstrada.
3. Para **confirmar IDs internos**, é indispensável uma fonte realmente independente do código IL e do `ReadOnlyProbe`, como uma base original ou ferramenta que obtenha o ID por método distinto e verificável. Preencher `reference_id` somente se a fonte efetivamente apresentar esse ID. Declarar `source_type=independent_database` ou `independent_tool`, descrever a origem, a versão e o método em `source_detail`.
4. Conferir os dois saves separadamente; coincidências entre dois logs do mesmo leitor são **repetibilidade**, não verificação externa. Se nomes, IDs ou origem forem ambíguos, deixar o campo de ID vazio e documentar a limitação.
5. Guardar um CSV de referência **separado** (não sobrescrever as observações): nome sugerido `fm2008-8.0.2v1-independent-reference-reviewed.csv`. Revisar e anexar manualmente as evidências de origem antes de considerar qualquer confirmação.

**Atenção:** o script não consegue provar que uma ferramenta seja independente nem que um revisor tenha consultado o jogo; essas afirmações dependem de auditoria humana. Não utilizar o FMRTE legado baseado no mesmo IL como fonte independente de ID.

## Executar o confronto offline

Em Python 3.10+:

```powershell
python .\scripts\verify_player_identification.py --observed .\research\builds\fm2008-8.0.2v1-observed-player-identities.csv --reference .\research\builds\fm2008-8.0.2v1-independent-reference-template.csv --output .\research\builds\player-id-cross-check.local.json
```

O comando deve ser executado a partir da pasta do repositório `FM2008.mapping`, **não** da pasta `FMRTE2008`. O template original retorna 0 IDs independentemente confirmados; somente uma referência revisada pode elevar essa contagem.

Para rodar os testes:

```powershell
python -m unittest discover -s tests -p test_verify_player_identification.py -v
```

## Critérios de interpretação

- `pending`: linha ainda não revisada (inclusive campos pré-preenchidos do template).
- `name_only`: nome conferido com proveniência registrada, mas ID não demonstrado independentemente.
- `id_and_name_match`: nome e ID coincidem com uma referência declarada independente e revisada. A credibilidade da origem ainda requer avaliação humana.
- `mismatch`: nome ou ID divergentes; investigar partida/posição, versão e eventual homônimo.
- `invalid_reference_id`: ID de referência fora do formato aceitável.

## Bloqueios preservados

Este procedimento **não altera** `NoApprovedPlayerMaps`, `MinimalPlayerIdentityMap.IsApprovedForOperationalUse`, nem a interface WPF demonstrativa. Não habilitar leitura de memória real ou edição com base em coincidência automática. Mesmo 10/10 correspondências documentais não substituem revisão manual do mecanismo de obtenção do ID, testes de realocação e tratamento de falhas.
